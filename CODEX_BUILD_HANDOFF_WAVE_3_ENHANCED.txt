# 6. Wave 3 architectural principles

Wave 3 introduces model-assisted semantics but does not make model output authoritative.

The canonical path is:

```text
nondeterministic semantic proposal
        ↓
strict structured schema
        ↓
deterministic semantic validation
        ↓
invariant validation
        ↓
typed event validation
        ↓
atomic event commit
        ↓
pure deterministic reduction
```

A model response is never canonical state merely because it parses.

Keep distinct:

```text
raw model response
parsed structured proposal
accepted canonical domain state
```

Replay must never re-call the model.

# 11. SemanticModelRuntime

Implement a narrow semantic-call runtime.

This is not the Wave 7 orchestrator.

For each semantic call:

1. resolve prompt definition;
2. verify prompt integrity;
3. resolve output schema;
4. verify schema integrity;
5. deterministically render minimal canonical input;
6. compute canonical semantic input hash;
7. derive idempotency key;
8. check persisted result for exact identity;
9. return the persisted result if reusable;
10. otherwise reserve model-call/token budget;
11. invoke provider-neutral StructuredModelPort exactly once;
12. persist raw response as content-addressed artifact;
13. settle/release budget;
14. classify/validate the structured result;
15. persist model-call provenance;
16. return the parsed proposal or typed failure for module semantic validation.

The semantic-call identity must include enough information to prevent incorrect reuse across prompt/schema/policy changes.

Conceptually:

```text
run_id
+ module_id
+ operation
+ canonical_input_hash
+ module_version
+ policy_hash
+ prompt_id
+ prompt_version
+ template_hash
+ output_schema_id
+ output_schema_version
```

Repeated execution with identical identity should reuse the persisted call result unless an explicitly versioned refresh policy says otherwise.

Replay never invokes this runtime.

# 13. Budget integration for semantic calls

No initial or repair model call may bypass the frozen Budget Meter.

Before a call reserve:

```text
1 LLM call
maximum permitted input token capacity
maximum permitted output token capacity
other required resource-vector values
```

After the call:

- settle known actual use;
- release unused reservation;
- preserve reported usage separately from policy charge.

If the adapter does not report token usage:

- actual usage stays unknown;
- policy charge may conservatively use the reserved amount;
- do not claim reserved tokens were observed actual usage.

A repair call is a second real call.

It consumes a second LLM-call budget unit.

If there is insufficient budget for the initial call:

- do not call;
- use deterministic fallback or blocker.

If there is insufficient budget for repair:

- do not overspend;
- use fallback or blocker.

# 14. Structured-output validation, repair, and fallback

Every model-assisted operation follows:

```text

→ strict Pydantic output-schema validation
→ module semantic validation
→ invariant/event validation
→ canonical event batch
```

If schema-invalid:

1. persist the invalid raw output;
2. allow at most one repair when operation policy permits and budget remains;
3. supply the original canonical request, invalid artifact ref, and concise validation errors;
4. meter repair as a separate model call;
5. validate the repaired payload from the beginning.

Maximum repair attempts:

```text
1
```

No third call.

A schema-valid but semantically invalid response must still be rejected.

Repair of semantic-invalid output is allowed only if explicitly enabled by versioned operation policy.

Repair and fallback are different:

```text
repair
= another model call

fallback
= deterministic code
```

Do not manually patch malformed model output and then claim it was valid model output.

Persist the path taken.
